# Оптимизация АэроУчёта

Этот файл ведётся как журнал технических изменений и итоговый чек-лист проверки на iPad.

## Уже выполнено

### Производные расчёты
- Кэшируются полётные смены.
- Кэшируется дневной индекс итогов.
- Кэшируются рейсы по дням.
- Кэшируются наземные события по дням.
- Кэшируется дата последней активности.
- Главная, Учёт и Календарь используют подготовленные данные вместо повторного полного расчёта при каждой перерисовке SwiftUI.

### Подготовка времён
- При построении смен хронология рейса больше не вычисляется многократно во время сортировки.
- FlightDuty может использовать уже подготовленные FlightTimeline.
- Производные данные приложения строятся одним подготовленным проходом по рейсам и рабочим событиям.

### Запуск приложения
- Во время чтения UserDefaults производные данные не перестраиваются после каждого загруженного массива.
- Загруженные данные не записываются обратно в UserDefaults просто из-за запуска приложения.
- После завершения загрузки производные данные строятся один раз.

### Мелкие оптимизации
- weekday DateFormatter переиспользуется.
- Демонстрационные рейсы удалены из production-инициализации. Существующие сохранённые данные пользователя не затрагиваются.

## Что пока намеренно НЕ меняем

- Миграцию основных данных с UserDefaults на SwiftData — это отдельный этап с обязательной миграцией существующих данных.
- Правило определения суток для workStart/plannedDeparture — бизнес-правило пока не подтверждено.
- Логику начисления расчётных часов по месяцу — правило даты атрибуции ещё не зафиксировано.

## Что проверить на iPad после текущего этапа

1. Приложение запускается (учитывая известное поведение Swift Playgrounds: первый Run App иногда не стартует, второй стартует).
2. Все ранее сохранённые рейсы и план работ на месте.
3. Главная показывает прежние месячные итоги.
4. Учёт показывает те же полётное, лётное, рабочее и ночное время.
5. Календарь показывает те же рейсы/работу на правильных датах, включая переход через полночь.
6. Добавление, редактирование и удаление рейса обновляет Главную, Учёт и Календарь сразу.
7. Добавление, редактирование и удаление плана работ обновляет эти экраны сразу.
8. Расчётное время: импорт, список версий, редактирование, undo/redo и удаление версии работают.
9. Проверить один двухсегментный рейс/смену и один рейс через полночь по известным контрольным значениям.
10. Проверить, что после перезапуска приложения изменения сохранились.

## Автоматическое качество — статический анализ

- CI расширен отдельным шагом `xcodebuild analyze` после обычной сборки iOS Simulator.
- Это добавляет проверку Xcode Static Analyzer без изменения поведения приложения и пользовательских данных.
- Опасный fallback `parseDate(...) ?? Date()` пока намеренно не меняется: корректное исправление требует явной стратегии обработки уже сохранённых некорректных дат, чтобы не изменить расчёты молча.
- На iPad для этого технического изменения отдельная функциональная проверка не требуется; достаточно общего чек-листа после объединения нескольких этапов.


## Инструменты контроля качества

- В отдельном workflow добавлены рекомендательные проверки SwiftLint и SwiftFormat: их замечания пока не блокируют сборку.
- Сборка сохраняет тайминги компиляции и исследует наличие готового simulator .app; если он создан, загружает архив как artifact на 7 дней.
- Доступность simulator .app для Swift Playgrounds package проверяется результатом CI; до подтверждения не считаем архив гарантированным.
- Appetize требует отдельного подключения и пригодного simulator .app.


## Регрессионные тесты расчётного времени

- Чистая математика времени вынесена в `AeroTimeMath.swift` без зависимости от SwiftUI.
- CI запускает отдельный набор быстрых проверок до полной сборки приложения.
- Зафиксированы контрольные случаи: обычный интервал, отрицательная разница, пересечение интервалов, распределение по суткам, границы ночи 22:00–06:00, переход через полночь, `dayKey`, `touchedDays` и зачёт домашнего резерва 1/4.
- Тест домашнего резерва пока фиксирует ТЕКУЩЕЕ поведение округления. Это не утверждение бизнес-правила; если правило будет подтверждено иначе, тест и расчёт меняются вместе отдельным этапом.
- `Package.swift` не изменялся: тестовый harness запускается отдельно через `swiftc`, поэтому Swift Playgrounds не должен перезаписывать или терять тестовую конфигурацию.


## Безопасная обработка сохранённых дат

- Добавлен строгий parser `parsedDate(date:time:)`: формат должен точно соответствовать `dd.MM.yyyy HH:mm`, невозможные даты/время отклоняются.
- Убран опасный сценарий, при котором ошибка разбора автоматически превращалась в текущее время через `?? Date()`.
- Для рейсов добавлена `validatedTimeline`; для наземных событий — `validatedDateRange`.
- Некорректные сохранённые записи не удаляются и не переписываются, но исключаются из производных расчётов, календарных индексов и сумм до исправления пользователем.
- Совместимые свойства `timeline`, `startDate`, `endDate` пока сохранены для UI; при некорректной записи они используют фиксированный технический placeholder 01.01.1970 вместо текущего времени, чтобы ошибка не попадала в текущий месяц/день.
- В регрессионные тесты добавлены невозможная дата, невозможное время и нек canonical формат.
- Следующий UI-этап: показывать пользователю явное предупреждение на некорректной записи вместо технического placeholder.
