# Оптимизация АэроУчёта

Этот файл ведётся как журнал технических изменений и итоговый чек-лист проверки на iPad.

- Состояние: рабочая версия непосредственно перед началом оптимизации.

## Уже выполнено

### Производные расчёты
- Кэшируются полётные смены.
- Кэшируется дневной индекс итогов.
- Кэшируются рейсы по дням.
- Кэшируются наземные события по дням.
- Кэшируется дата последней активности.
- Главная, Учёт и Календарь используют подготовленные данные вместо повторного полного расчёта при каждой перерисовке SwiftUI.

### Подготовка времён
- При построении смен хронология рейса больше не вычисляется многократно во время сортировки.
- FlightDuty может использовать уже подготовленные FlightTimeline.
- Производные данные приложения строятся одним подготовленным проходом по рейсам и рабочим событиям.

### Запуск приложения
- Во время чтения UserDefaults производные данные не перестраиваются после каждого загруженного массива.
- Загруженные данные не записываются обратно в UserDefaults просто из-за запуска приложения.
- После завершения загрузки производные данные строятся один раз.

### Мелкие оптимизации
- weekday DateFormatter переиспользуется.
- Демонстрационные рейсы удалены из production-инициализации. Существующие сохранённые данные пользователя не затрагиваются.

## Что пока намеренно НЕ меняем

- Миграцию основных данных с UserDefaults на SwiftData — это отдельный этап с обязательной миграцией существующих данных.
- Правило определения суток для workStart/plannedDeparture — бизнес-правило пока не подтверждено.
- Логику начисления расчётных часов по месяцу — правило даты атрибуции ещё не зафиксировано.

## Что проверить на iPad после текущего этапа

1. Приложение запускается (учитывая известное поведение Swift Playgrounds: первый Run App иногда не стартует, второй стартует).
2. Все ранее сохранённые рейсы и план работ на месте.
3. Главная показывает прежние месячные итоги.
4. Учёт показывает те же полётное, лётное, рабочее и ночное время.
5. Календарь показывает те же рейсы/работу на правильных датах, включая переход через полночь.
6. Добавление, редактирование и удаление рейса обновляет Главную, Учёт и Календарь сразу.
7. Добавление, редактирование и удаление плана работ обновляет эти экраны сразу.
8. Расчётное время: импорт, список версий, редактирование, undo/redo и удаление версии работают.
9. Проверить один двухсегментный рейс/смену и один рейс через полночь по известным контрольным значениям.
10. Проверить, что после перезапуска приложения изменения сохранились.
