- Временная вкладка Test принята пользователем в текущем виде и больше не нужна.

## Баги / требования к следующему пакету

### 1. Дополнительный текст PDF
- Повторный импорт перспективного PDF **не исправил** текст отпуска.
- На экране по-прежнему видна искусственная пунктуация/разрыв: `...повышение . квалификации...` (пример ноябрь 2025).
- Нужно искать реальную причину в разборе/хранении текста, а не только в отображении уже сохранённой строки.

### 2. Редактирование уже сохранённой истории
- В карточке существующего задания истории при редактировании номер рейса сейчас не запускает автоподстановку из расписания.
- Требование: механизм должен быть **тем же, что и при создании нового задания**.
- После изменения номера рейса должны пересчитываться маршрут и плановые времена leg/duty по импортированной базе.
- Это допустимо, потому что есть отмена редактирования и отдельное подтверждение сохранения.

### 3. Новый ручной FlightDuty — начальные значения и тип ВС
- Предустановленный борт для нового ручного задания: **RA-73772 (Тарасов)**.
- Он должен сразу давать эксплуатационный тип **A320S**.
- Автоподстановка типа ВС должна происходить **сразу при вводе пятой цифры**, без ухода/blur из поля.
- Выбор типа ВС через всплывающее меню отменяется. По тапу на поле типа тип циклически переключается в порядке:
  `A320 → A320S → A320N → A321 → A321S → A321N → A320 ...`
- Если борт заполнен и пользователь вручную переключил тип, цифровой RA-борт очищается.

### 4. Терминалы
- Терминалы других аэропортов не нужны.
- У Шереметьево обычные B/C также не показывать: достаточно `SVO`.
- Исторические редкие терминалы **D/E/F** Шереметьево можно сохранить и показывать.
- Применить правило одинаково в ручном задании и перспективном плане/карточке.

### 5. Удаление добавленного leg при создании
- При создании нового задания можно добавить 2-й/3-й leg, но сейчас нельзя убрать ошибочно добавленный.
- Требование: карточку конкретного leg можно свайпнуть влево → появляется кнопка удаления → leg удаляется.
- После удаления должны корректно пересчитываться границы смены и соседние leg.

### 6. Перспективный план — производительность
- Открытие раздела «Перспективный» после тапа занимает примерно **7 секунд**.
- Открытие FlightDuty по тапу на рабочее назначение также заметно тормозит (около 7 секунд).
- Нужно профилировать/найти причину; не переносить тяжёлые поиски/полный проход по базе в SwiftUI `body`.

### 7. Перспективный план — сверка маршрута
- Маршрут визуально теперь полезно берётся из расписания и устранил старые проблемы (например Махачкала).
- Нужно **сверять** маршрут перспективного PDF с маршрутом из расписания.
- Если номер/дата нашлись, но аэропорты источника и расписания конфликтуют, это должно всплывать как конфликт/ошибка, а не молча подменяться.

### 8. Перспективная карточка FlightDuty
- Должна закрываться теми же способами, что обычная карточка: свайпом вниз и тапом по свободной области (когда не идёт редактирование).
- Карточка должна иметь те же кнопки **редактировать / удалить** и тот же редактор, что сохранённая история.
- Номер задания для перспективного FlightDuty: дата назначения, например `02.06.2026` (пользователь также проговорил вариант с префиксом `P`, но финально склоняется к дате после «Задание на полёт №»; префикс считать незафиксированным до реализации).
- Терминальные правила и автоподстановка рейса/борта/типа должны быть одинаковыми с остальными FlightDuty.

### 9. Автоприсвоение борта в перспективной карточке
- Для A320-family пользователь хочет автоматически подставлять реальный борт из справочника и сохранять его в карточке.
- Явно прозвучал борт **73772 (Тарасов)** как желаемый для A320/A320S контекста.
- Для A321 пользователь предложил выбирать случайный подходящий реальный борт и сохранять выбранный результат в конкретной карточке.
- Точная матрица «тип → фиксированный/случайный борт» проговорена неоднозначно и перед кодированием должна быть сверена с текущим справочником; не угадывать типы.

### 10. Test
- Временная вкладка Test принята; её можно удалить.

### 11. Экран «Воздушные суда»
- Две строки легенды `A-320 → A320 ...` / `A-321 → A321 ...` пользователю непонятны и не нужны на этом экране — убрать.
- Список уже идёт по RA-номерам; сохранить сортировку, но **RA-73772 / Тарасов вывести первым**, затем остальные по порядку.

### 12. Экран «Расписание рейсов»
- Импортированный файл должен быть не просто записью в истории импортов.
- Пользователь должен иметь возможность **открыть импортированную базу**, листать строки и искать.
- Нужен поиск по ключевым полям (как минимум номер рейса, маршрут/аэропорты; при реализации можно добавить даты/тип ВС без изменения основного требования).
