# 04.10.2026 22:58 МСК — Компактный просмотр расписания, тип ВС и формат номера рейса

## Запрос Дениса
- База расписания около 3000 строк должна отображаться компактнее: много свободного места, нужен табличный вид.
- Добавить фильтр/выпадающий выбор семейства ВС (минимум: A320-family, B737, A330, A350, B777; плюс «Все»).
- Сырые коды A320-family из расписания показывать привычными типами: `320→A320`, `32A→A320S`, `32N→A320 Neo`, `321→A321`, `32B→A321S`, `32Q→A321 Neo`.
- При создании/редактировании полётной смены по номеру рейса и выбранной дате из расписания должны подтягиваться маршрут, времена и конкретный тип ВС на этот день.
- Перспективный план должен использовать тот же date-specific lookup типа ВС.
- Борт назначать случайно, но подходящий под тип ВС и, когда будет надёжная БД компоновок, под компоновку; результат должен сохраняться в карточке. Для A320S закрепить RA-73772 (Тарасов) как специальное правило.
- Номера рейсов в предметной области только 3- или 4-значные: `6→006`, `24→024`, `100…999` — три цифры, `1000…9999` — четыре.

## Предлагаемая архитектура (без кода)
- Исходные 2795 строк не агрегировать и не терять: компактность только на UI-слое.
- Просмотр расписания сделать плотной таблицей: `Рейс | Маршрут | UTC время | Тип | Компоновка | Полётное | Период/дни`; подробности строки — по тапу.
- Фильтр семейства + поиск + опциональный фильтр «на дату» резко уменьшают объём видимых строк.
- Внутри хранить raw aircraft code для диагностики, наружу показывать нормализованный тип.
- Автоподстановка задания: дата + номер рейса → конкретная активная строка расписания → маршрут/времена/тип/компоновка.
- Если на одной дате один и тот же номер неоднозначен по маршруту, не угадывать: использовать существующий маршрут при редактировании либо показывать выбор/конфликт.
- Случайный борт должен быть стабильным (выбран один раз для duty/совместимой группы leg и сохранён), а не меняться при каждом открытии.
- Live-поиск номера не должен переписывать поле во время набора: `6` используется как lookup для `006`, но пользователь может продолжить ввод до `640`; канонический `006/024/640/1000` показывать после завершения ввода/в режиме просмотра.
