# 09.10 10:44 · ChatGPT · Компиляция в Playgrounds и GitHub Actions — разные сборки
- **Вопрос:** почему при каждом ▶️ Run в Swift Playgrounds на iPad приходится ждать, если GitHub Actions уже компилирует AeroUchet; что можно ускорить без точного замера времени.
- **Ответ:** существующий `.github/workflows/ios-ci.yml` собирает `-destination generic/platform=iOS Simulator` с `CODE_SIGNING_ALLOWED=NO`, создаёт ZIP для симулятора; GitSync переносит исходники, не готовый подписанный пакет для физического iPad. Playgrounds локально подготавливает/собирает и запускает свой app playground, может использовать кэш, но сборка CI его кэша не заменяет.
- **Разобрали:** минутное ожидание ▶️ Run необязательно является временем runtime-старта приложения. Отдельно измерить время компиляции/подготовки Playgrounds, первый кадр приложения, загрузку AppStore/AbsenceStore/AssignmentPlanStore; самостоятельно запускать уже установленное приложение — другой сценарий.
- **Варианты:** (1) использовать App Preview для несложных проверок внешнего вида; (2) измерить холодный и повторный Run, оптимизировать реальные узкие места; (3) ускорить CI параллельной подготовкой симулятора и пакетными скриншотами; (4) в перспективе отдельная подписанная сборка для iPad/TestFlight через Apple Developer Program — это устранит компиляцию Playgrounds при каждом запуске готового приложения, но потребует подписи, организации распространения и безопасного переноса данных между контейнерами.
- **Статус:** планирование, код приложения и CI не изменялись, команда «Программируй» не получена. Существующие GitHub/.memory остаются обязательными.
