# 10.10 14:22 · ChatGPT · Сборка и загрузка Simulator: зависимости

- **Вопрос пользователя:** можно ли запускать Simulator и сборку параллельно? Не сломается ли последовательная проверка новой версии? Объяснить фактический процесс выпуска на примере изменения колонок базы воздушных судов.
- **Проверены CI-файлы GitHub:** в `.github/workflows/ios-ci.yml` текущие jobs `build` (macos-26) и `simulator-smoke` (macos-26, `needs: build`) выполняются последовательно **на разных эфемерных раннерах**. Собранный ZIP доступен второму только после загрузки/скачивания artifact. Smoke в `Scripts/ci-simulator-smoke.sh` загружает iPad Pro 12,9″ 3rd gen / iOS26.5 / landscape / dark, устанавливает тестовый .app, снимает только главный экран, сохраняет изображения. Шаг `continue-on-error: true` — зелёный workflow не гарантирует успех smoke, проверять `status.txt`.
- **Строгие зависимости:** изменение Swift → commit/PR → компиляция актуального commit → упаковка .app → установка в booted Simulator → открытие → скриншот. **Само включение iPad Simulator независимо от содержимого .app** и может идти одновременно с компиляцией после создания PR/checkout того же commit. Но установка старого файла под видом новой версии запрещена. Для одного runner нужен async `simctl boot/bootstatus` во время `xcodebuild`, затем явная проверка успешного завершения обеих задач и установка свежего app. Простое параллельное выполнение двух независимых macOS jobs не поможет разделить boot, поскольку их виртуальные устройства не общие.
- **Неоправданная параллельность:** начинать CI на недописанных изменениях или пытаться запускать Simulator на эфемерном GitHub-hosted runner до появления PR нельзя считать рабочей схемой; раннер выделяется под конкретный workflow. Досрочный старт возможен на постоянно работающем self-hosted Mac, но это другая инфраструктура.
- **Фактическая цепочка AeroUchet:** ассистент меняет Swift в ветке, PR запускает core tests, build, analyze, quality, privacy, simulator smoke; после проверки merge в main; `.github/workflows/auto-version.yml` после Swift push в main поднимает `AppVersion.swift`, затем GitSync на iPad, локальная сборка Playgrounds. Скриншот PR может содержать старый номер версии при новом Swift-коде (версия меняется после merge). Прежний smoke **не открывает базу ВС и не проверяет геометрию колонок**, только запуск и главную страницу; визуальная проверка требует автоматизированных переходов/UI-тестов или физического iPad.
- **Риски экспериментального совмещения:** недостаточно CPU/RAM macOS runner (конкуренция), зависание boot/GUI rotation, screenshot не с того commit, ложный зелёный статус. Ускорение нельзя обещать; замерить минимум пару полных прогонов до/после, сохранить автоматические регрессионные и privacy checks; не трогать SwiftUI/расчёты.
