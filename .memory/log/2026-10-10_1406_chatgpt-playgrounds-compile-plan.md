# 10.10 14:06 · ChatGPT · Сколько занимает Run и как диагностировать компиляцию
- Пользователь: минутный Run в Swift Playgrounds нормален ли, нужно ли ускорять, что такое диагностическая сборка и какие есть инструменты; пока не может проверить на iPad.
- По видео два полных ожидания Swift-заставки 61 и 58 секунд, среднее 59,5 с (n=2). Это не норматив и не точное время работы компилятора; короткие возвраты 3–7 секунд не доказывают быстрой повторной компиляции.
- По репозиторию 31 Swift-файл (~0,93 МиБ). По GitHub CI SwiftCompile занимает суммарно 116,543 сек. параллельных задач двух архитектур симулятора — это не wall-time и не iPad Run. Основная Build job ~2:07.
- По Apple и Swift.org нет официального общего среднего Run для Swift Playgrounds. Грубые ориентиры 5–15 с для маленьких, 15–45 с для средних, 30–90+ с для больших проектов являются оценкой, а не бенчмарком Apple; оборудование iPad 2019 года влияет.
- Следующий шаг по новой команде «Программируй»: отдельная вручную запускаемая диагностическая CI-сборка с флагами Swift frontend -warn-long-expression-type-checking=100 и -warn-long-function-bodies=100, Build Timing Summary и списком самых медленных файлов/строк; сравнить несколько полных и инкрементальных сборок до/после. Это измеряет компиляцию GitHub, а не непосредственно iPad.
- После измерений возможны точечные упрощения SwiftUI View body и сложных выражений, явные типы, отдельные subviews; дробление файлов само по себе не гарантирует ускорения. Не менять генерируемый Package.swift.
- Остальные варианты: инструментировать время первого кадра и синхронной загрузки AppStore на iPad; пакетные скриншоты за один Simulator boot; в перспективе подписанный билд/TestFlight, отдельно решить перенос данных.
- Десятикратное ускорение Run не обещать, пока не измерены bottlenecks. Если минутный Run терпим, срочная переработка программы не требуется. Код и CI в данном ответе не менялись.
