# 11.10 16:21 · ChatGPT · Предварительный прогрев Simulator до окончания правок
- Пользователь предложил запускать Mac/симулятор до завершения правок Swift-кода: мгновенный черновой PR и прогрев, затем дописать код и обновить PR. Просит перепроверить якобы ограничение выделения серверов до PR и узнать о потребности в дополнительных серверах.
- GitHub официально поддерживает выделение hosted runner при workflow_dispatch (без PR), push и PR-событиях; VM выдаётся на время job и затем уничтожается. Стандартные GitHub-hosted runners бесплатны для публичных репозиториев (но есть лимиты одновременных работ и таймауты). Источники: https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow ; https://docs.github.com/en/actions/how-tos/manage-runners/github-hosted-runners/use-github-hosted-runners ; https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax ; https://docs.github.com/en/actions/reference/runners/github-hosted-runners .
- Актуальный .github/workflows/ios-ci.yml: pull_request + workflow_dispatch, concurrency group включает номер PR и cancel-in-progress: true. При изменении чернового PR GitHub отменит прежний run вместе с загруженным на нём симулятором. PR без реального diff не нужен; если изменить только .memory/**, paths-ignore исключит автоматический CI. В текущем workflow_dispatch запускается полный CI по существующему SHA, который сам по себе не сохранит загруженный симулятор между runs.
- Потенциальное решение (только план): отдельный долгоживущий prewarm workflow на временном Mac №2, запускать отдельным сигналом (workflow_dispatch вручную либо push специального файла ветки через доступный GitHub connector); прогреть iPadOS и держать job открытым до появления артефакта от окончательного PR. По команде после готовности Swift-кода запускать обычный build Mac №1, проверять commit SHA и run ID, скачивать строго свежую сборку и устанавливать в сохранённый симулятор. Раздельные concurrency-группы, TTL/timeout, явная проверка успеха CI, предотвращение stale builds обязательны.
- Дополнительные серверы не нужны: используются те же два временных macOS jobs, только ранняя подготовка симулятора. Начинать полноценную сборку до окончания редактирования бессмысленно — она соберёт старую версию. После завершения изменений сборка всё равно занимает около двух минут. Ускорение ожидается ограниченное (обычно десятки секунд до ~минуты, зависит от длительности разработки, очередей и загрузки). Нет бенчмарка этой схемы.
- В доступном GitHub connector нет прямого инструмента workflow_dispatch; для запуска из этого чата придётся добавить отдельный триггер по push, либо пользователь может запустить вручную. Предварительный PR — не оптимальная реализация.
- Статус: обсуждение/план, без новой команды «Программируй», приложение v186/CI не менялись. Следующее действие — отдельный диагностический PR при разрешении.
