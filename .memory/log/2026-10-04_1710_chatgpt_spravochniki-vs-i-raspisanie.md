## Справочник воздушных судов
Нужен единый локальный справочник. Пользовательский тип ВС нормализовать до ровно 6 вариантов:
1. `A320`
2. `A320S`
3. `A320N`
4. `A321`
5. `A321S`
6. `A321N`

Сопоставление кодов истории:
- `A-320` → `A320`
- `A-320A` → `A320S`
- `A-320N` → `A320N`
- `A-321` → `A321`
- `A-321B` → `A321S`
- `A-321Q` → `A321N`

Основная таблица справочника в приложении:
- тип ВС (один из 6);
- новый регистрационный номер `RA-xxxxx` (в карточке Денис вводит цифровую часть);
- фамилия;
- старый регистрационный номер `VP-…`/исторический;
- MSN сохранить как справочное поле из Numbers, но не обязательно показывать в основной таблице;
- точную техническую модификацию (A320-214, A321-211, A321-251NX…) можно сохранить скрыто для будущего;
- компоновку пока НЕ использовать.

Код типа из истории не нужно повторять в каждой строке — лучше хранить отдельным общим mapping шести типов.

## Поведение поля «Тип ВС / Бортовой номер» в карточке задания

- Денис вводит цифровую часть текущего RA-регистрационного номера.
- Когда редактирование ячейки бортового номера закончено (ячейка становится неактивной после тапа вне неё), приложение ищет борт в справочнике и автоматически ставит его тип ВС.
- Если борт найден — тип заменяется типом из справочника.
- Если пользователь вручную выбирает другой тип ВС при уже введённом борте — бортовой номер очищается, чтобы не оставить несовместимую пару.
- Старый регистрационный номер и фамилия нужны справочно и не обязаны отображаться в самой карточке полёта.

## Импорт расписания рейсов
В Настройках добавить импорт расписания `.xls` (формат типа `Draft.xls`).
- `Вид перевозки` игнорировать полностью; все эти записи считать плановыми.
- Сохранять номер рейса, период, дни выполнения, IATA аэропортов, терминалы, UTC-время отправления/прибытия, код ТВС, компоновку/сырой код при необходимости, полётное время.
- Хранить загруженные периоды и не создавать дублей при повторном импорте.
- Время из расписания конвертировать UTC → Москва при использовании в карточке.
- Для неоднозначных случаев одного номера в один день использовать маршрут; если при ручном создании без маршрута остаётся несколько вариантов — не угадывать, а дать выбрать вариант.

## Автозаполнение по номеру рейса
Триггер — завершение редактирования ячейки номера рейса (не отдельный `onSubmit` клавиатуры).
После номера + даты найти запись расписания и заполнить:
- маршрут + IATA + терминалы;
- включение двигателей = плановое время отправления расписания;
- выключение двигателей = плановое время прибытия расписания;
- взлёт = включение + 8 минут;
- посадка = выключение − 8 минут;
- плановое полётное время = выключение − включение (оно же столбец полётного времени расписания);
- плановое лётное время = посадка − взлёт = полётное − 16 минут;
- начало работы полётной смены = за 1:00 до включения первого лега;
- завершение работы полётной смены = через 0:30 после выключения последнего лега.

Ранее согласованное `взлёт = +10 минут` отменяется новым правилом `+8 минут`; руление после посадки также 8 минут.

## Перспективный план
Расписание становится источником разбиения рабочего задания на физические леги:
- не делить общее время перспективной смены математически;
- для каждого номера рейса найти свою запись расписания и создать отдельный лег с его собственным маршрутом/временами/полётным;
- маршрут из перспективного плана помогает разрешить неоднозначность;
- сумма полётных времён легов должна проверяться против общего планируемого полётного времени строки PDF; при расхождении не исправлять молча, а считать это ошибкой/требованием проверки;
- пассажирское перемещение остаётся отдельным событием и не является полётной сменой/легом рабочей смены.
