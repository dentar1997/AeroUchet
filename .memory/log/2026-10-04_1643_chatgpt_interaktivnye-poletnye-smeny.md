# Интерактивные полётные смены перспективного плана

**Дата:** 04.10.2026 16:43 МСК
**Агент:** ChatGPT
**Статус:** требования зафиксированы, код не менять до нового «Программируй»

## Что сообщил Денис

### Текст связки рабочий → пассажир
- Итоговая строка в Test/перспективном плане должна быть в виде:
  `Полётная смена + Перемещ. в кач. пассаж. = H:MM ≤ Макс. продолж. полётной смены + 02:00`.
- Сокращения/начала смысловых частей писать с прописной: `Перемещ.`, `Макс.`.
- В тестовом SU 1000 сейчас странность: показывается длительность полётной смены, но нет полётного времени. Это нужно исправить в следующем пакете/при интеграции карточки.

### Дополнительный текст PDF
- v128 снова проявил старую ошибку при склейке строк отпуска: получается что-то вроде `...заработной платы, повышение. квалификации...`.
- Нужна одна строка без смещения на следующую строку.
- Точки/иная пунктуация, возникшие только из-за переноса строки PDF, должны исчезать; смысловая пунктуация исходной фразы сохраняется.

### Правый столбец перспективного плана
- Вернуть более компактный прежний размер шрифта даты и времени.
- Год в датах внутри месячной карточки не показывать: `14.12–17.12`, `18.12` и т. п.; год уже указан в заголовке карточки месяца.
- Серую/третью строку с вычисленными границами полётной смены (`−1:00/+0:30`) убрать из видимости списка перспективного плана. Эти значения понадобятся внутри карточки задания на полёт.

### Интерактивная карточка рабочего рейса
- На данном этапе интегрировать в перспективный план **только карточку задания на полёт для рабочих полётных смен**.
- Каждая рабочая полётная смена в перспективном плане становится интерактивной: нажатие открывает ту же карточку задания на полёт, что используется в истории полётов.
- Пассажирское перемещение, отпуск и прочие наземные назначения пока не интерактивны: для них позже будут отдельные карточки.
- Перемещение пассажиром **не является полётной сменой и не является частью полётной смены**, даже если непосредственно предшествует/следует рабочему рейсу.

### Как предварительно заполнять карточку из перспективного плана
Из импортируемого перспективного плана для рабочего задания:
- исходный первый временной интервал трактовать как внешние опорные времена включения/выключения двигателей;
- начало работы = первое включение двигателей − 1:00;
- взлёт первого лега = первое включение двигателей + 0:10;
- завершение работы = выключение двигателей последнего лега + 0:30;
- номер рейса/рейсов, маршрут и дата импортируются из перспективного плана;
- расчётное время пока `Нет данных`, поскольку нормативная база ещё не подключена; существующий механизм карточки (`Из таблицы`, ручное значение и т. п.) переносится без упрощений;
- разделение общего интервала/общего полётного времени между двумя и более легами пока **не определено** — Денис отдельно продумает правило.

### Вид строки рабочего рейса в перспективном плане
- Префикс `SU` в визуальном отображении перспективного плана убрать; сами данные номера рейса не терять.
- Пример: вместо `SU 1426 ...` показывать `1426 · Шереметьево (SVO/B) → Челябинск (CEK) · A320`.
- К названиям аэропортов добавить IATA-коды; для Шереметьево дополнительно терминал через `/B`, `/C` и т. п.
- В истории полётов позже также заменить обобщённое `Москва` на `Шереметьево`/SVO, но это отдельная последующая правка.

### Борт и база ВС
- RA-73772 / A320 приведён Денисом как пример закреплённого борта для тестовой/будущей карточки; не считать это универсальным хардкодом для всех рейсов.
- Отложить отдельную базу ВС: текущий бортовой номер → тип ВС → старый бортовой номер → MSN → компоновка.
- Позже эта база должна использоваться для заполнения карточек.
