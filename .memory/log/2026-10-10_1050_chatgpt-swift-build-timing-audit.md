# 10.10 10:50 · ChatGPT · Компилятор — основной потребитель CPU при сборке
- **Запрос:** «Продолжай» — продолжить аудит 50–60-секундного ожидания после ▶ Run в Swift Playgrounds на iPad. Нового «Программируй» не было, код и CI менять запрещено.
- **Проверено по живому main:** 31 Swift-исходник без генерируемого `Package.swift`, ~978071 байт (~0,93 МиБ). Крупнейшие: `AppViews.swift` 158 КиБ, `ReferenceDataV129.swift` 110 КиБ, `CalendarView.swift` и `FlightNorms.swift` ~62 КиБ.
- **Прямые данные CI:** в сборке GitHub Actions run 37869623157 / build job 113624455716, `xcodebuild -showBuildTimingSummary` сообщает `SwiftCompile (6 tasks) | 116.543 seconds`, `SwiftDriver | 5.454 s`, `SwiftEmitModule | 5.136 s`, `Ld | 1.930 s`. **Это сумма длительностей параллельных задач, включая arm64 и x86_64 симулятора**, не календарное время и не замер на физическом iPad. Swift-компиляция доминирует над линковкой по времени задач. Весь build job ~2:07, а отдельный boot iPad Simulator занимал около четырёх минут из общего CI ~7:34.
- **Код после запуска:** `MyApp.swift` лёгкий `WindowGroup(ContentView)`. `ContentView.swift` содержит `@StateObject` AppStore/AbsenceStore/ProductionCalendarSyncModel/AssignmentPlanStore. `AppStore.init` синхронно загружает историю по месяцам, события и перестраивает derived data + LegTimelineCache; `AssignmentPlanStore.init` загружает план и обращается к Keychain, `AbsenceStore.init` читает файл. Это **возможные** источники задержки первого кадра при больших данных, но **не доказано**, что они занимают существенную долю минуты на iPad. Профиль iPad 12,9″ / landscape / dark остаётся обязательным.
- **Видео:** полные последовательности Swift-заставки около 61 и 58 секунд. Короткие возвращения 3–7 секунд необязательно являются независимыми пересборками после Run (могут быть переключением на готовое приложение); нельзя делать из них строгий вывод о 3-секундном холодном запуске.
- **Технически подтверждённый путь диагностики компиляции:** во временном диагностическом CI-прогоне добавить Swift frontend флаги `-Xfrontend -warn-long-function-bodies=100` и `-Xfrontend -warn-long-expression-type-checking=100` (или `-debug-time-`), собрать рейтинг самых медленных функций/выражений, в первую очередь крупных SwiftUI View body. Сначала диагностика, затем малые точечные правки только доказанных hotspot; дробление файлов само по себе не обещает ускорения. Не редактировать генерируемый `Package.swift`.
- **Маршрут ускорения:** A) с разрешения «Программируй» отдельный диагностический PR для compiler timings без изменения приложения; B) изменение компиляторных hotspots с сравнением времени сборки, CI, откатами; C) раздельные показатели первой отрисовки и подготовки данных на физическом iPad, не записывая персональные данные в публичные логи; D) пакетные UI-скриншоты и уменьшение cold boot CI; E) опционально подписанная сборка/TestFlight для запусков вне Playgrounds, с отдельной защитой и переносом пользовательских данных. Это разные цели, не путать.
- **Надёжные источники:** исходники и build log GitHub Actions; Apple support `https://support.apple.com/guide/playgrounds-ipad/run-your-app-itc650868b1f/ipados`; официальные документы компилятора `https://github.com/swiftlang/swift/blob/main/docs/CompilerPerformance.md`.
- **Итог:** статический аудит углублён, app-code/CI не менялись. Следующий технический шаг ждёт новую команду «Программируй». Ожидаемый коэффициент ускорения неизвестен до измерений.
