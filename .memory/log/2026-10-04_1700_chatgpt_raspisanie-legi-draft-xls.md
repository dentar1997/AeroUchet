# 04.10.2026 17:00 — Draft.xls: расписание как источник данных по легам

Денис прислал `Draft.xls` и предложил использовать расписание рейсов для разбиения полётной смены перспективного плана на отдельные леги с собственными временами.

## Что проверено
- Файл старого формата Excel BIFF8, лист называется `UTC`.
- 2795 строк данных, 14 колонок: номер рейса; начало/конец периода; дни выполнения; аэропорт/терминал/время вылета; аэропорт/терминал/время прилёта; тип ВС; компоновка; полётное время; вид перевозки.
- Диапазон именно этого файла: 05.10.2026–24.10.2026. Это не полный март–октябрь, а конечный фрагмент летнего расписания; для других месяцев потребуются соответствующие версии/файлы расписания.
- 768 уникальных номеров рейсов, 326 направлений, 95 аэропортов, 14 кодов типов ВС.
- Все ключевые поля заполнены во всех 2795 строках; пустыми бывают только терминалы там, где терминал не задан.
- У всех 2795 строк дата начала и дата конца периода соответствуют указанным дням выполнения.
- Для всех 2795 строк `время прилёта UTC − время вылета UTC` (с переходом через сутки) в точности совпадает со столбцом `Полетное время`. Несовпадений 0.

## Однозначность поиска
Алгоритм-кандидат: номер рейса + дата выполнения по периоду/дню недели + маршрут.
- При разворачивании расписания получается 9749 физических выполнений легов.
- По ключу `номер рейса + дата` неоднозначность только в одном случае: SU1707 23.10.2026 — VVO→KJA и KJA→SVO под одним номером в один день.
- Добавление пары аэропортов `вылет→прилёт` снимает неоднозначность полностью: 0 дублей.
- Значит, надёжный ключ должен включать маршрут, а не только номер и дату.

## Проверка знакомого Ханты-Мансийска
На 11.10.2026:
- SU1382: SVO/B 22:00 UTC → HMA 00:55 UTC, тип 32B, C16Y167, полётное 2:55.
- SU1383: HMA 01:55 UTC → SVO/B 05:05 UTC, тип 32B, C16Y167, полётное 3:10.
- Сумма двух легов = 6:05.
Это совпадает по номерам/маршруту со знакомой связкой SU1382/SU1383 для Ханты-Мансийска из перспективных планов; точное сравнение с суммарным временем строки 10.26 ещё нужно выполнить по исходному PDF/данным.

## Важные ограничения
- Времена в таблице — UTC. AeroUchet работает в московском времени, поэтому при интеграции нужна явная конвертация UTC→Москва (+3), с сохранением операционной даты расписания. 9% физических выполнений вылетают после 21:00 UTC и после перевода в Москву переходят на следующую календарную дату; простое сравнение только по московской дате будет ошибочным.
- 15.8% строк пересекают полночь UTC.
- Таблица даёт тип/компоновку, но не бортовой регистрационный номер RA-...; борт нужно получать из другого источника/БД.
- Коды типа ВС в расписании (например 32A, 32B, 321, 73B и др.) требуют собственной таблицы соответствия человекочитаемому типу.
- Значения `Вид перевозки` встречаются как J/S/C/G/P; смысл кодов пока не определён, не угадывать.
