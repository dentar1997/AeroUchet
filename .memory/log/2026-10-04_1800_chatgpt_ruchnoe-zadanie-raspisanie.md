# Ручное создание задания + база расписания

Денис уточнил логику создания нового задания на полёт и использования импортированной базы расписания.

## Номер рейса
- В интерфейсе номер рейса показывать только цифрами, без дефисов и без `SU`: `1110`, `1111`, `1000`, `1001`.
- Первый лег пользователь вводит/выбирает сам.
- При `Добавить рейс` следующий номер предлагается как обратная пара от **последнего реально выбранного лега**:
  - если предыдущий номер чётный → следующий `+1` (нечётный);
  - если предыдущий нечётный → следующий `-1` (чётный).
- Примеры: `1110 → 1111 → 1110`; `1001 → 1000 → 1001`.
- Если пользователь вручную изменил номер очередного лега, дальнейшая автоподстановка строится уже от нового номера, а не от исходной цепочки.

## Автозаполнение из импортированного расписания
- Расписание не вшивается в код: пользователь импортирует `.xls` в приложении, оно сохраняется в отдельной локальной базе и используется для автоподстановки.
- После ввода номера рейса и завершения редактирования/снятия активности поля приложение ищет подходящую строку расписания на выбранную дату.
- Таблица расписания хранит UTC; перед заполнением карточки времена переводятся в московское время.
- По расписанию автоматически подставляются маршрут и времена включения/выключения двигателей.
- Базовая логика планового лега:
  - `engineOn` = плановое время отправления из расписания;
  - `takeoff` = `engineOn + 8 мин`;
  - `engineOff` = плановое время прибытия из расписания;
  - `landing` = `engineOff - 8 мин`;
  - для первого лега `workStart = engineOn - 1:00`;
  - для последнего лега задания `workEnd = engineOff + 0:30`.
- При добавлении следующего лега предыдущий перестаёт быть последним: его `workEnd` становится равным `engineOff`; `workStart` нового лега начинается от завершения работы предыдущего лега (существующее поведение карточки).
- Новый последний лег получает `workEnd = engineOff + 0:30`.
- Все события получают корректную дату после пересчёта из UTC в Москву; если время переходит через 00:00, дата соответствующего события автоматически увеличивается на сутки.
- Дата нового задания по умолчанию может быть сегодняшней; поиск расписания должен учитывать именно московскую дату включения двигателей после UTC→MSK, чтобы вечерние рейсы не сопоставлялись с неверными сутками.
- Все такие записи из расписания считаются плановыми; поле `Вид перевозки` расписания пока не используется.

## Перспективный план
- Та же база расписания должна использоваться для раскрытия рабочего назначения перспективного плана на отдельные физические леги: номер + дата + маршрут → конкретная строка расписания с собственным временем лега.

Код пока не менять до нового слова `Программируй`.
