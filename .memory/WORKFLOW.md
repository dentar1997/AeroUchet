# Как работать с Денисом и с проектом

## Правила общения (накоплены за 22–30.09)
1. **Кодовое слово «Программируй»** (27.09). До него только обсуждаем, уточняем и предлагаем. Код, ветки и PR не трогаем. После слова сразу выполняем **весь** согласованный пакет.
2. **Делать сразу и полностью.** Не писать «ТЗ» вместо работы, не выдавать половину сделанного за готовое, не говорить «нет доступа», когда он есть. Это вызывало у Дениса сильное раздражение (25.09, 26.09).
3. **Правки вносит ассистент в репозитории сам.** Денису код вставлять не нужно. Ему говорим только, что проверить после синхронизации. Исключение — если Денис сам просит фрагмент.
4. Если Денис всё же вставляет код руками: только **файл целиком** или «найди этот фрагмент → замени целиком». Никаких «добавь внутри struct».
5. **Не путать хронологию.** Перед ответом «где остановились» нужно проверять дату и время последних сообщений и код в main. Ошибка ChatGPT 29.09 — назвал последней старую версию.
6. Номер версии виден на «Главной». С 04.10 (v122) его поднимает автоматическая проверка после каждого изменения `.swift` в `main` и делает коммит «Версия N: …» — по нему в GitSync видно, что пришла новая версия. Вручную не поднимать.
7. Перед рискованными экспериментами — резервная ветка (`backup/...`). Откат делать **новым коммитом поверх**, а не сдвигать main назад: иначе GitSync снова отправит старую версию (урок 27.09).
8. Если Денис просит картинку или эскиз, показываем изображение, а не описание словами.
9. Клавиатура: отдельная задача «в конце, после визуала» (27.09). Без запроса её не трогать.
10. Ответы короткие и по делу, на русском. Денис часто пишет голосом, поэтому в тексте встречаются ошибки распознавания («ТПС/TFS» = тип ВС, «лаги» = леги, «Era тире» = «RA-»).

## Инструменты и окружение
- **Mac нет.** Разработка в **Swift Playgrounds на iPad Pro 2019**. Проект в Playgrounds: `AeroUchet-GitSync.swiftpm` в папке «На моём iPad».
- Синхронизация: **GitSync** (бесплатно), кнопка Sync Now или «Синхронизировать изменения». Working Copy — резерв (Pro-функция связи с документом взята 10-дневным триалом 24.09). В «Командах» iOS есть сценарий Sync Now → «Открыть файл .swiftpm», дальше Open и Run App вручную.
- Особенности Playgrounds:
  - Preview убивается при обновлении дольше 5 с; длинные файлы компилируются минутами → держать файлы меньше и логику вне body;
  - **никогда не нажимать «Delete App Data & Restart»** — сотрёт данные;
  - бывает «X.swift not in a target», новые файлы иногда не добавляются в target;
  - первый Run может упасть, второй проходит;
  - Package.swift и `.swiftpm/playgrounds` принадлежат Playgrounds: Package.swift не править без нужды, служебные файлы — в .gitignore;
  - физическая клавиатура в App Preview глючит (баг Playgrounds), особенно после системного окна «Файлы».
- TestFlight не используется (Apple Developer $99/год — «пока без подписки»).
- **GitHub:** аккаунт `dentar1997`.
  - `AeroUchet` — **публичный** (с 26.09, ради бесплатных macOS-раннеров), код приложения.
  - `AeroUchet-Private` — приватный архив: дословные чаты ChatGPT, разбор, реконструкция чата 1, личные вложения из чатов в `archives/attachments/` (с 04.10 вобрал AeroUchet-Claude2; Workflow удалён).
  - **Живая память — `.memory/` в AeroUchet** (с 04.10), см. [README.md](README.md).
  - Личные данные (выгрузки .xls, ICS-токен) **не класть в публичный репозиторий**.
- CI (`.github/workflows/ios-ci.yml`, `quality.yml`): свои регрессионные тесты (`Scripts/run-core-time-tests.sh`, `run-test-event-cleanup-tests.sh`) + сборка под iOS Simulator + `xcodebuild analyze` + SwiftLint/SwiftFormat (только проверка) + артефакт AeroUchet-Simulator.zip. Запускается на PR. Иногда падает только шаг загрузки артефакта — помогает перезапуск job.
- CI подтверждает сборку, но **не поведение на iPad**. Касания, клавиатуру и вид проверяет Денис.

## Быстрые CI-скриншоты — тёплый iPad (12.10, PR #204; U53, P14)
- **UI-задача:** **сразу после «Программируй», до правок Swift** — создать ветку `prewarm/<тема>` от свежего `main` и **сразу отправить её в GitHub** (push пустой ветки). Тёплый iPad включится сам (автозапуск с 13.10). Он же включается от любого push в `prewarm/*`, если был выключен. Ручной запуск на всякий случай: `gh workflow run early-ipad-prewarm.yml -f request_epoch=$(date +%s)`.
- Сессия (одна на репозиторий) за 4–6 мин грузит iPad 12,9″, ставит тёмную тему и поворот, собирает `main` и прогревает систему. Пока идёт работа над кодом, это скрыто. Затем **каждый новый SHA** открытых PR из `prewarm/*` она сама собирает инкрементально и снимает: **33–41 с от push до снимка**. Ошибки компиляции публикуются сразу. Живёт до 2 ч без правок и до 5,5 ч всего (с 12.10 23:43; было 25 мин) — значит, обычно один прогрев на весь вечер, в том числе на следующие задачи: новая ветка `prewarm/*` подхватывается без прогрева. Когда работа закончена — `-f mode=stop`. Повторный запрос поглощается; `-f mode=restart` — перезапуск (нужен, если менялись сами скрипты CI), `-f mode=stop` — остановить.
- **Где снимок:** ветка `ci-shots` → `shots/<SHA>/` (`*.jpg`, `proof.json`, `capture.log`, тайминги). Claude: `python3 Scripts/ci_ipad.py fetch-shot --sha <SHA> --dest <папка>` (только git; артефакты Actions из среды Claude не скачиваются). Артефакт `ipad-shot` в PR CI — для ChatGPT и Дениса.
- **Какие экраны:** по умолчанию таблица ВС (`--aerouchet-ci-aircraft-tamm`). Другие — `.github/prewarm/shots.json` в ветке PR; новые экраны требуют CI-аргумента запуска в приложении (это код, только по «Программируй»).
- **Гарантии:** PR зелёный только со снимком своего коммита (или своего run ID), RAW без портретной рамки, тёмная тема, приложение живо. Без тёплой сессии build job снимает сам (~10 мин) — медленно, но PR не зависает.
- **Остальные PR (метод А):** параллельный job грузит iPad вместе со сборкой; 4–7 мин, снимки «Главная» и «База ВС». Медленно из-за только что загруженного iPad, поэтому для UI-задач — тёплая сессия.
- CI-only изменения не поднимают AppVersion. Подробнее — `log/2026-10-12_1308_claude_warm-ipad-result.md`, `.github/prewarm/README.md`.

## Что Денис ценит
- Наглядность и проверяемость: «если увижу своими глазами — обалдею» (удаление и загрузка календарей).
- Сверку с реальными данными (суммы времени совпали с порталом до минуты).
- Предложения вариантов с выбором, а не единственное «я решил».
- Плавность на iPad Pro 120 Гц.

## Переход между чатами (почему память в репозитории)
В ChatGPT чаты упирались в лимит (AeroUchet 1 → 2 → Branch → 3 → «Рабочая ветка» → «Актуальная версия» → «Продолжение» → «Настройка парсера»), и каждый раз контекст терялся. С 30.09 Денис хочет **один канонический источник контекста в репозитории**, который ассистент читает в начале работы и сразу дополняет новыми решениями и аргументацией.
