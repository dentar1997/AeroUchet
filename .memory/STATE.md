- Если на дату строки нет, данные другого периода не подставлять.
- Компоновку пока хранить справочно.

## Плановые времена
- `engineOn = scheduled departure`.
- `takeoff = engineOn + 8 мин`.
- `landing = engineOff − 8 мин`.
- `engineOff = scheduled arrival`.
- UTC расписания переводить в Москву.
- Первый `workStart = engineOn − 1:00`, последний `workEnd = engineOff + 0:30`.
- Следующий парный рейс: чётный `+1`, нечётный `−1` от последнего реально выбранного leg.

## Номер рейса — live-поиск
- Поиск выполняется после каждой введённой цифры, без blur.
- Для поиска ведущие нули эквивалентны (`10 = 0010`, `100 = 0100`, `7 = 0007`).
- Пока пользователь печатает, нули автоматически в поле не дописывать; после успешного ввода/в просмотре использовать канонический 3/4-значный формат.
- Промежуточное несуществующее значение не очищает последнюю успешную автоподстановку.

## Воздушные суда
- Рабочие типы: `A320`, `A320S`, `A320N`, `A321`, `A321S`, `A321N`.
- `RA-73772 / Тарасов` закреплён как специальный борт для A320S.
- Для остальных типов планируется выбирать подходящий реальный борт из справочника и сохранять выбор в задании.
- При вводе пятой цифры RA тип определяется сразу.
- Тап по типу циклически переключает 6 вариантов.
- **Уточнение 05.10:** префикс `RA-` в поле борта всегда видим. При смене типа очищается только цифровая часть (`RA-73772 → RA-`). Первый Backspace убирает 5 цифр и оставляет `RA-`; следующий Backspace не стирает `RA-`, а возвращает предыдущие 5 цифр. Это ждёт реализации.

## Перспективный план
- Рабочие назначения открывают тот же `DutyAssignmentOverlay`, что история.
- Номер перспективного задания = дата `dd.MM.yyyy`.
- Редактированные значения перспективной карточки сохраняются локально.
- Удаление перспективной карточки удаляет соответствующее назначение; механизм «Были конфликты» не менять.
- Пассажирские перемещения и наземные назначения пока неинтерактивны.
- План ≠ факт: перспективные данные не попадают в фактический налёт/зарплату.
