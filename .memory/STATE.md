## v133 — календарь выполнения рейса (ждёт проверки)
- Причина v132: верхний контрол даты был обычным системным `DatePicker`; он не мог показывать дни выполнения конкретного рейса.
- При точном поиске существующего рейса с одним маршрутом верхняя дата теперь открывает `FlightExecutionCalendarV131View`.
- Календарь отмечает реальные даты выполнения внутри загруженного покрытия и с учётом текущего фильтра ВС.
- Текущая выбранная дата визуально отличается от остальных дней выполнения.
- Если выбранный месяц входит в покрытие рейса, календарь открывается на нём; иначе — на первом месяце выполнения.
- При нескольких маршрутах один номер не объединяется молча: остаются route-specific варианты.
- Остальные ранее обсуждавшиеся улучшения браузера (`Время МСК`, полное `Полётное время`, `Вид перевозки`) сейчас не приоритет; возвращаться только при реальной потребности.

## Плановые времена
- `engineOn = scheduled departure`.
- `takeoff = engineOn + 8 мин`.
- `landing = engineOff − 8 мин`.
- `engineOff = scheduled arrival`.
- UTC расписания переводить в Москву.
- Первый `workStart = engineOn − 1:00`, последний `workEnd = engineOff + 0:30`.
- Следующий парный рейс: чётный `+1`, нечётный `−1` от последнего реально выбранного leg.

## Номер рейса — live-поиск
- Поиск выполняется после каждой введённой цифры, без blur.
- Для поиска ведущие нули эквивалентны (`10 = 0010`, `100 = 0100`, `7 = 0007`).
- Пока пользователь печатает, нули в активное поле не дописывать.
- Промежуточное несуществующее значение не очищает последнюю успешную автоподстановку.
- При неоднозначности по номеру+дате маршрут обязателен; молча выбирать нельзя.

## Перспективный план — постоянные правила
- Рабочие назначения открывают тот же `DutyAssignmentOverlay`, что история.
- Номер перспективного задания = дата `dd.MM.yyyy`.
- Редактированные значения перспективной карточки сохраняются локально.
- Удаление перспективной карточки удаляет соответствующее назначение.
- Пассажирские перемещения и наземные назначения пока неинтерактивны.
- План ≠ факт: перспективные данные не попадают в фактический налёт/зарплату.
- Маршрут PDF строго сверять с расписанием; конфликт показывать, молча не заменять.
- **Механизм «Были конфликты» не менять.**
- Будущая синхронизация расписания относится только к перспективному плану, не к истории факта.
