## v130 — рейс и редактирование FlightDuty
- Автоподстановка расписания теперь работает одинаково при создании нового задания и редактировании уже сохранённой истории.
- Поиск рейса выполняется **после каждой введённой цифры**, без ухода из поля.
- Ведущие нули эквивалентны: `10 = 0010`, `100 = 0100`, `7 = 0007`. До успешного совпадения введённые нули не выбрасываются; найденный номер канонизируется после подстановки.
- Если промежуточный номер не существует (`10` найден → набрали `100`), уже подставленные маршрут/времена не очищаются; при дальнейшем валидном `1000` данные сразу меняются.
- Новое ручное задание предустановлено `RA-73772 / A320S`.
- При вводе пятой цифры RA тип ВС определяется сразу, без blur.
- Поле типа ВС больше не меню: обычный тап циклически `A320 → A320S → A320N → A321 → A321S → A321N → A320`; ручная смена типа очищает борт.
- Добавленный второй/третий leg в режиме создания можно удалить свайпом влево; после удаления пересчитываются workStart/workEnd оставшихся leg.

## v130 — расписание рейсов
- База по-прежнему импортируется пользователем из BIFF8 `.xls`, лист `UTC`; файл в приложение не вшивается.
- `FlightScheduleStoreV129` теперь держит индекс по нормализованному номеру рейса вместо полного `entries.filter` по всей базе на каждый lookup. Это исправляет установленную причину ~7-секундной задержки перспективного UI; фактическую скорость нужно подтвердить на iPad.
- Повторный импорт обновляет/добавляет строки по устойчивому ключу; номер рейса в ключе нормализован (`0010` и `10` не создают разные сущности).
- `Ещё → Расписание рейсов`: добавлено `Открыть базу расписания`; база листается и ищется по номеру, IATA/названию аэропорта, типу ВС.
- Все скачиваемые файлы могут называться `Draft.xls`, поэтому в списке импортов главным названием теперь служит **период покрытия**; ниже — число строк и дата/время импорта. Имя файла не используется как основной идентификатор.
- Проверенный источник `Draft.xls`: 2795 строк, 05.10–24.10.2026; полётное время = UTC-интервал 2795/2795.
- **Анализ Draft.xls 04.10 22:52:** 326 направленных пар аэропортов; 272 встречаются повторно. Только 61/272 имеют одно и то же полётное время во всех строках, у 211/272 (77,6%) время различается. Медианный разброс 15 мин; максимум VVO→SVO 8:20…9:40 (80 мин). Даже при одинаковых `номер рейса + маршрут` время меняется: 241 из 583 повторяющихся групп. Маршрут сам по себе не задаёт фиксированное полётное время.
- **A320-family 04.10 22:56:** коды расписания согласуются как `320=A320`, `32A=A320S`, `32N=A320N`, `321=A321`, `32B=A321S`, `32Q=A321N`. Всего 1918 строк. При одинаковом маршруте и одинаковом точном коде ВС время меняется в 200/278 повторяющихся групп (71,9%); даже при одинаковых `номер рейса + маршрут + код ВС` — 137/482 (28,4%). Для одного `номер рейса + маршрут` с разными A320-family кодами медианное время различается только в 33/243 группах (13,6%); тип ВС полезен как атрибут, но не задаёт время сам по себе.
- Плановые времена: `engineOn = вылет`, `takeoff = +8 мин`, `landing = −8 мин`, `engineOff = прилёт`; UTC→Москва; первый workStart −1:00, последний workEnd +0:30.

## v130 — маршруты и терминалы
- Терминалы в рабочих маршрутах скрываются везде, кроме исторических **SVO/D, SVO/E, SVO/F**. SVO/B, SVO/C и терминалы других аэропортов не показываются.
- Известные IATA-алиасы канонизируются через `AirportDatabase` (например старый/новый код одного аэропорта не считается ложным конфликтом).
- Перспективный PDF строго сверяется с расписанием по номеру/дате/маршруту. Если номер/дата найдены, но маршрут отличается, показывается конфликт/ошибка и молчаливой подмены маршрута нет.

## v130 — перспективный план
- Рабочие назначения открывают **тот же `DutyAssignmentOverlay`**, что история полётов, а не отдельную упрощённую карточку.
- Поддерживаются те же закрытие тапом по свободной области / свайпом, редактирование и удаление.
- Редактированные значения перспективной карточки сохраняются локально по ID назначения и используются при повторном открытии.
- Удаление перспективной карточки удаляет соответствующее назначение перспективного плана; механизм «Были конфликты» не менялся.
- Номер перспективного задания = дата назначения `dd.MM.yyyy`, например `Задание на полёт № 02.06.2026`.
- Для A320/A320S используется реальный `RA-73772` (Тарасов); для остальных семейств выбирается стабильный реальный борт соответствующего типа из справочника, чтобы он не менялся при каждом открытии.

- Сумма полётного времени легов из расписания по-прежнему сверяется с общим плановым временем PDF; несовпадение показывается для проверки.
