## v131 — расписание и автозаполнение (ждёт проверки на iPad)
- `Ещё → Расписание рейсов → Открыть базу расписания`: плотная таблица вместо больших карточек.
- Сверху: дата, фильтр `Все ВС / A320 / B737 / A330 / A350 / B777`, поиск по рейсу/аэропорту.
- Строка: рейс · маршрут · UTC-время · тип ВС · полётное время. Тап раскрывает период, дни выполнения, исходный код и компоновку.
- Точный номер рейса ищется по всей импортированной базе. Если на выбранную дату рейс не выполняется, показываются маршрут(ы) и `Календарь выполнения`.
- Календарь отмечает только реальные дни внутри загруженного покрытия и учитывает текущий фильтр ВС. Один номер на разных маршрутах показывается отдельными вариантами.
- Номера в просмотре канонические: `6→006`, `24→024`, `640`, `1000`. Во время активного ввода нули автоматически не дописываются.
- A320-family расписания: `320→A320`, `32A→A320S`, `32N→A320N`, `321→A321`, `32B→A321S`, `32Q→A321N`.
- Автоподстановка в новом задании, истории и перспективном плане использует только конкретную строку, покрывающую дату (`validFrom...validTo` + дни выполнения) и маршрут при неоднозначности. Данные другого периода не подставлять.
- Из конкретной строки берутся маршрут, времена, `flightMinutes` и тип ВС.
- По типу выбирается стабильный реальный RA-борт. **A320S закреплён за RA-73772 / Тарасов**; для остальных типов — стабильный подходящий борт из справочника. Компоновка пока справочная/часть seed, не жёсткая привязка.
- Перспективный план показывает тип ВС и полётное время из строки расписания соответствующей дате.

## Редактор FlightDuty — RA-
- Префикс **`RA-` всегда видим**.
- Ручная смена типа ВС очищает только цифровую часть: `RA-73772 → RA-`.
- На заполненном пятизначном борте первый Backspace очищает все 5 цифр и оставляет `RA-`.
- Следующий Backspace не стирает `RA-`, а возвращает предыдущие пять цифр.
- Реализация вошла в v131; ждёт проверки на iPad.

## Плановые времена
- `engineOn = scheduled departure`.
- `takeoff = engineOn + 8 мин`.
- `landing = engineOff − 8 мин`.
- `engineOff = scheduled arrival`.
- UTC расписания переводить в Москву.
- Первый `workStart = engineOn − 1:00`, последний `workEnd = engineOff + 0:30`.
- Следующий парный рейс: чётный `+1`, нечётный `−1` от последнего реально выбранного leg.

## Номер рейса — live-поиск
- Поиск выполняется после каждой введённой цифры, без blur.
- Для поиска ведущие нули эквивалентны (`10 = 0010`, `100 = 0100`, `7 = 0007`).
- Пока пользователь печатает, нули в активное поле не дописывать.
- Промежуточное несуществующее значение не очищает последнюю успешную автоподстановку.
- При неоднозначности по номеру+дате маршрут обязателен; молча выбирать нельзя.

## Перспективный план — постоянные правила
- Рабочие назначения открывают тот же `DutyAssignmentOverlay`, что история.
- Номер перспективного задания = дата `dd.MM.yyyy`.
- Редактированные значения перспективной карточки сохраняются локально.
- Удаление перспективной карточки удаляет соответствующее назначение.
- Пассажирские перемещения и наземные назначения пока неинтерактивны.
- План ≠ факт: перспективные данные не попадают в фактический налёт/зарплату.
- Маршрут PDF строго сверять с расписанием; конфликт показывать, молча не заменять.
- **Механизм «Были конфликты» не менять.**

## Терминалы
- В рабочих маршрутах терминалы не показывать, кроме исторических `SVO/D`, `SVO/E`, `SVO/F`.
- Обычные `SVO/B`, `SVO/C` и терминалы других аэропортов скрывать.
