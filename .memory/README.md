# Живая память АэроУчёта — инструкция для ЛЮБОГО ИИ

Claude, ChatGPT, Copilot и любой другой ИИ работают с **одной** памятью: этой папкой.
Папка скрытая (начинается с точки): Swift её не компилирует, Playgrounds и «Файлы» на iPad её не показывают. На GitHub она видна.

Пользователь — **Денис**, второй пилот A320/321, база SVO, время **московское**. Пишет часто голосом («лаги» = леги, «ТПС» = тип ВС). Отвечать по-русски, коротко.
Приложение — SwiftUI, Swift Playgrounds на iPad, **Mac нет**. Код: GitHub → GitSync → iPad. CI на PR.

---

## 1. Начало любого разговора (2–3 минуты, не больше)
1. Прочитай [STATE.md](STATE.md) — где проект сейчас, что ждёт проверки.
2. Прочитай **последние 3 файла** в [log/](log/) (имена сортируются по времени, последний — самый новый).
3. Прочитай [DECISIONS.md](DECISIONS.md) — что решено и **что нельзя повторять**.
4. Если речь о коде — посмотри живой `main`: `AppVersion.swift`, `git log -10`, открытые PR.
5. Короткие реплики Дениса («И?», «то же для…», «не работает») понимай через последние записи журнала. **Не проси пересказывать.**
6. Если Денис в первом сообщении сообщает результат проверки («работает», «не работает», скриншот) — **сначала запиши это** (раздел 3), потом всё остальное.

Остальные файлы читать только по теме — таблица в разделе 5.

## 2. Когда писать запись в журнал
Журнал — это конспект разговора. Пишет тот ИИ, с которым Денис сейчас говорит. Записи идут **друг за другом**, кто бы их ни писал.

Писать запись **сразу**, без просьбы Дениса, когда:
- Денис поставил задачу, сказал требование или принял решение;
- обсуждение пришло к выводу (даже если код не менялся);
- изменён код или документы;
- Денис сообщил результат проверки на iPad;
- **перед долгой работой** — короткая запись «начинаю: …» (если ИИ зависнет или чат оборвётся, следующий увидит, что было начато);
- чат подходит к пределу или Денис уходит — запись «передача».

Не надо писать запись на каждую реплику. Одна запись = один законченный кусок разговора. Лучше 5 коротких записей, чем одна потерянная длинная.

## 3. Как писать запись
Новый файл в `log/`: **`ГГГГ-ММ-ДД_ЧЧММ_<ии>_<тема>.md`** (время московское; ии: `claude`, `chatgpt`, `copilot`).
Пример: `log/2026-10-04_0115_chatgpt_svod-istochnikov.md`. Тема — латиницей, 1–4 слова через дефис.

```markdown
# 04.10 01:15 · ChatGPT · Сведение источников плана
- **Денис:** что просил или сообщил — его словами или близко к тексту
- **Обсудили / решили:** вывод и почему; что отвергли
- **Сделано:** файлы, коммит, PR, версия (или «код не менялся»)
- **Статус:** обсуждение · согласовано, ждёт «Программируй» · в работе · ждёт проверки на iPad · ✅ Денис проверил · ❌ не помогло
- **Дальше:** что делать следующему ИИ
```

Правила:
- **Чужие записи не переписывать.** Исправление или новый статус — новой записью со ссылкой на старую.
- Если запись меняет общее положение — обнови и [STATE.md](STATE.md) (версия, «ждёт проверки», следующий шаг). Новое решение — строкой в [DECISIONS.md](DECISIONS.md) со ссылкой на запись.
- Цитаты Дениса — коротко. Длинные переписки целиком не копировать: дословный архив хранится отдельно (раздел 6).
- **Никаких личных данных** — репозиторий публичный: без выгрузок .xls, ICS-ссылки и токена, номеров заданий, сумм зарплаты, PDF планов. Личное — в AeroUchet-Private.
- «Готово» ≠ «CI прошёл» ≠ «Денис проверил». ✅ ставить только по словам Дениса. Молчание — не подтверждение.

## 4. Правила для каждого ИИ
**Все:** код приложения — только после слова **«Программируй»** (до него обсуждаем и предлагаем варианты). **Версию вручную не трогать:** после каждого изменения `.swift` в `main` автоматическая проверка (`.github/workflows/auto-version.yml`) сама поднимает номер в `AppVersion.swift`, пишет хеш, PR и дату и делает коммит «Версия N: …». Денису сообщать, какую версию ждать на «Главной» (текущий номер + 1). Откат — новым коммитом поверх. В интерфейсе ничего не должно «прыгать».

**ChatGPT** (обсуждение и планы, без лимитов):
- Старт нового чата: прочитать этот файл по разделу 1. Никаких многоэтапных Workflow, квитанций и «Saved ✓» — старый Workflow отменён 04.10.
- Один ответ — один шаг. Если работа длинная — сначала запись «начинаю», потом работа, потом запись итога.
- Писать в журнал напрямую в `main` (только файлы `.memory/`). Если записать в GitHub не получается — **так и сказать** и выдать готовый текст записи блоком, чтобы Денис вставил его сам или переслал Claude.
- Когда Денис говорит **«зафиксируй»** — запись в `log/` и строка в DECISIONS.
- Чат стал длинным или тормозит — запись «передача» (что обсуждали, что решили, что открыто) и предложить новый чат.

**Copilot** (задачи в этом репозитории):
- Запись журнала и обновление STATE — **в той же ветке и том же PR**, что и код. Задача без записи не завершена.
- Проверить [DECISIONS.md](DECISIONS.md) → раздел «Не повторять» перед исправлением бага.

**Claude** (исполнитель крупных задач, аудиты — работа лимитирована, поэтому на нём большие проверки):
- Код по «Программируй», ветка → PR → CI → слияние.
- Периодический аудит памяти: свести журнал в STATE, DECISIONS, FEATURES, HISTORY_INDEX; убрать противоречия; старые записи `log/` за прошлые месяцы переносить в `log/archive/ГГГГ-ММ/`.

## 6. Дословный архив (вне этого репозитория)
- **ChatGPT:** раз в неделю или после большого этапа Денис делает экспорт данных ChatGPT и загружает `conversations.json` в приватный архив **AeroUchet-Private**; Claude запускает `scripts/build_archive.py` — получаются дословные чаты с ID сообщений.
- **Claude:** ссылка на сессию — в каждом коммите и PR.
- **Copilot:** переписка — это сам PR и его коммиты.
- Скриншоты и видео: нелично — в комментарий PR; лично — AeroUchet-Private.
